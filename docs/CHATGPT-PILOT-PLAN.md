# Wyreup private ChatGPT pilot

Baseline: origin/main `4e32bf9e6a99c4bbd9729c2fb29bcf5ecfa24e7d`.
Task: `wyreup-chatgpt-private-pilot`. This is a new delivery task, separate from the completed SEO/security release.

## Scope

Create a private ChatGPT MCP plugin for exactly three workflows: compress one JPEG/PNG/WebP to a target KB, strip metadata from one JPEG/PNG/WebP, and merge two to five PDFs in the supplied order. Reuse `@wyreup/core` processors. Keep the existing local-path MCP and public website unchanged.

A new private workspace package holds the adapter, a result card, tests, and a setup/runbook. No npm publication or public directory submission is required for this private pilot. Do not expose arbitrary local paths, arbitrary remote URL fetching, or the full core registry.

## Transport and files

Use the official Secure MCP Tunnel with a stdio server. Only OpenAI's tunnel client gets access to the three bounded tools; no inbound public listener. The operator must supply a tunnel associated with their ChatGPT workspace and a runtime key using secret configuration, never source control or chat output. Platform sign-in is complete; the scoped tunnel draft is prepared but uncreated, and the runtime key is still pending.

Each tool's file schema declares `download_url`, `file_id`, optional `mime_type`, and optional `file_name`, with only the first two required; declare the top-level file field in `openai/fileParams`. Validate the complete arguments server-side, including unknown properties and file count. Use downloaded signatures to infer supported types rather than trusting MIME labels or filename suffixes.

Download host configuration defaults to empty, denying all downloads. Populate exact hostnames only after observing a synthetic ChatGPT upload; tests may separately configure the already-public fixture origin. Lowercase DNS names, reject trailing dots, wildcard/suffix matches, IP literals, URL credentials/fragments, and ports other than omitted/443. Use only HTTPS. Resolve A and AAAA, normalize mapped IPv4 addresses, and reject the hostname if any answer is non-global (including private, loopback, link-local, CGNAT, documentation, benchmark, reserved, unspecified, ULA, and multicast addresses). Pin a checked address in the HTTPS connection's lookup callback while keeping original allowlisted hostname for TLS SNI and certificate verification. Follow no redirects; accept only HTTP 200 with no content encoding. Do not log input names, IDs, signed URLs, or bytes. A 20-second deadline covers DNS, connect, and download; 8 MiB per file and 24 MiB per request total apply to declared and actually buffered bytes, stopping before retaining excess data. MCP incoming JSON has a 64 KiB cap. Process at most one job concurrently; reject excess requests with a retryable error. Finally blocks destroy partial streams, clear timers, terminate the owned worker, release buffers and the single-flight slot on success, failure, timeout, or cancellation.

Declare compress as one file, `target_kb` integer 10–10240 default 200 and `allow_downscale` boolean default true; strip as one file; merge as an ordered 2–5 file array. Strict argument schemas reject unknown fields. Expose only `compress_image_to_size`, `strip_image_metadata`, and `merge_pdfs`. Set conservative readOnlyHint false, openWorldHint true, destructiveHint false; hints never authorize access. No local-path, chain, registry, Pro key, or Pro origin arguments are exposed.

All signature checks, Sharp header metadata inspection, mandatory validation decoding, PDF parsing/page counting, and transforms run inside the disposable worker, after its hard deadline has been armed. None of this parsing/decoding runs on the controller thread. Image signature validation precedes Sharp header metadata preflight with a 16 megapixel limit; reject animation/multiple frames and unsupported formats. Use the already-installed Sharp version explicitly rather than a handwritten format parser. Decode every accepted image with the core codec even when compression would pass it through; compare decoded/header dimensions. For PDFs, signature validation and strict `PDFDocument.load` (without ignoreEncryption) reject encrypted/malformed inputs and over 100 combined pages before the core merge copies any pages. Counting a general PDF's page tree requires parsing; do not claim a page count can be established before a PDF parser runs. The parser is contained by the hard process memory boundary and byte/time caps.

Run the complete stdio adapter inside a reviewed Docker image: non-root, read-only root filesystem, no host mounts, no public ports, capabilities dropped, no-new-privileges, 64 PIDs, two CPUs, and a hard 1 GiB memory limit with memory-swap also 1 GiB. Trusted code reads its bundled assets; job files are never written. Bundle only the three selected core processors and the SDK; pinned runtime dependencies are the three jSquash codecs, pdf-lib and Sharp. Record the official Node base-image digest and audit the complete resulting dependency graph. The host tunnel key is not passed into the container. Downloads use the bounded HTTPS adapter. Transform work runs in a disposable worker with scrubbed environment, 128 MiB V8 heap budget and a 60-second hard deadline. Terminate only that owned worker on timeout/cancellation; discard captured stdout/stderr from codecs. Worker heap limits do not cap native/WASM allocations: the enclosing Docker memory limit supplies that boundary. Container exhaustion can disconnect a call rather than return a friendly tool error; it must never produce a false success, and a fresh managed runtime must be verified usable afterward. A direct Node run may be used for test seams, never represented as the isolated pilot runtime.

## Result and download

Return concise structured metadata (output MIME, fixed output filename, bytes, actual target reached, PDF page count/order when applicable). An unreachable compression target is an explicit tool error; do not attach a successful download or claim the requested limit was met. Disclose that an over-target PNG can become JPEG and lose transparency. Metadata stripping bakes orientation then re-encodes pixels (JPEG/WebP quality 95), removes container metadata, and does not redact visible content. PDF merging preserves document contents; it does not sanitize active content.

Attach a minimal accessible MCP Apps result card using the official SDK 1.x-compatible `@modelcontextprotocol/ext-apps` bridge (1.7.5), bundled without third-party fetches. Instantiate the actual bridge as `new PostMessageTransport(window.parent, window.parent)`; reject unrelated-window messages in an executed test. The SDK logs full parsed messages at debug level; use esbuild `--drop:console` for the widget bundle so those logs cannot expose file bytes or input URLs. Verify the built widget contains no SDK console calls and captured browser logs contain no input/output canaries. Accept messages from the parent window only, with the standard SDK schema validation and request correlation; ignore unknown/replayed responses. Handle one bounded result per widget instance and ignore duplicate deliveries. Clear the result on cancellation/teardown. Deliver at most 8 MiB raw output bytes in result `_meta`, never in model-visible content; enforce a 12 MiB complete JSON envelope ceiling before returning the result and before sending a widget download request. These are application ceilings, not claims about unknown host limits; real ChatGPT verification must include a near-ceiling output and can lower the ceilings if necessary. Include raw-byte SHA-256; verify decoded length and hash in the widget before any download. Do not retain results in a server store.

On an explicit Download action, use the standard `App.downloadFile` / `ui/download-file` method when the host advertises `downloadFile` capability. Pass one embedded resource containing the verified output's `blob` (base64), MIME, and fixed `file:///compressed.jpg`-style identifier. This URI names inline data; it neither asks the server to read a local file nor exposes a filesystem path. There is no resource-link URL, uploadFile call, navigation, public download endpoint, library saving, or fallback upload path. Keep widget CSP connect/resource/redirect domains empty. Feature-detect the advertised host capability; if absent, show an unsupported-host message rather than claim a download worked. Treat host `isError`, denial, cancellation, timeout and connection loss as failure, clear pending state, and let the user retry explicitly. Disable duplicate concurrent clicks and do not automatically retry a failed or ambiguous download. This standard route is established in the actual SDK 1.7.5 app.d.ts/spec.types.d.ts, but ChatGPT implementation support remains unverified until all three real ChatGPT workflows and on-disk downloads pass. If it fails, reassess the documented host-supported output path in a new scoped plan; do not substitute a local path or invent file references.

No analytics or third-party assets. State explicitly on the card and in the runbook: input uploads and output bytes/tool responses pass through OpenAI; processing runs on the operator's host; the standard host-mediated download sends the result through ChatGPT too. Wyreup does not write or keep server-side job files. The result remains available in the mounted ChatGPT card until cancellation/teardown, and OpenAI's own retention policies apply. Do not claim the whole flow is local or no-upload. Existing browser-native site privacy claims must not be copied to this integration.

## Measured output-ceiling amendment

The initial reviewed plan above retains its original 8 MiB output and 12 MiB envelope proposals. The native standard SDK 1.32.1 stdio client rejected an 8 MiB inline result: its serialized response was 11,185,356 bytes, exceeding the unchanged 10 MiB ReadBuffer. The same client accepted a 7 MiB result with exact bytes and SHA-256; its response was 9,787,256 bytes. The implementation therefore lowers raw output to 7 MiB and its result/widget envelope ceiling to 10 MiB under the plan's existing permission to lower measured transport ceilings. Input limits remain 8 MiB per file and 24 MiB aggregate. The original failure and success are preserved in `checker/default-stdio-envelope-v3/result.json` under the evidence directory. This measurement proves standard SDK compatibility at that synthetic boundary, not actual ChatGPT support. All actual-host download and saved-file acceptance gates still apply. Prior plan reviews and the former-source review remain historical evidence; corrected source requires a new final review.

## Reviewed shared processor repair

Independent native checks found that the reused core helper handled JPEG orientation only. Stripping PNG or WebP metadata removed the orientation tag without rotating the stored pixels. This expands the original unchanged-core scope: a narrowly renewed Grok plan review approved repairing `packages/core/src/lib/exif.ts` while retaining its public signatures, existing eight pixel transformations and browser-compatible dependencies. Bounded JPEG APP1, PNG eXIf and WebP EXIF readers supply a shared bounded TIFF orientation reader; malformed metadata remains identity and cannot be read across segment or chunk boundaries. Existing processors continue to reuse this helper. Regression tests cover supported containers, both byte orders, all eight transformations, malformed lengths/offsets/types/counts, and actual oriented codec output. A patch Changeset covers core and its CLI/MCP consumers. Promotion requires fresh public deployment and npm parity checks. The renewed plan PASS approves the approach; corrected-source, isolated-runtime and actual ChatGPT acceptance remain separate gates.
