# Receipt batch: partial implementation

Status: incomplete and hard-disabled. `receipt-batch-to-csv-pro` is not in the client registry or server pricing table. For an authenticated request that passes CSRF, the server returns 503 after reading the bounded JSON envelope but before image parsing, credit reservation or inference. No configurable flag enables it. The local schema, CSV formatter and standalone editable review component are not connected to a product surface. No receipt data is forwarded to an inference provider or charged by this implementation.

The intended flat price is **3 credits per batch**, provisional. One image costs the same as three. The published inference tariff does not prove a worst-case image-token charge for the chosen workload; therefore no claim that the price covers every run is established. No paid benchmarks or model calls were performed.

Before enabling: implement and independently review bounded image container validation, animation rejection, safe decoding and pixel limits; apply orientation and deterministic metadata removal across web, CLI and MCP; provide explicit upload consent that resets when files change; integrate and accessibility-review the standalone editable review component; implement a bounded one-call-per-image adapter with no retry or post-timeout dispatch; establish truncation and no-result refund behavior; integrate the shared idempotency and output-recovery lanes; verify provider privacy terms, actual billing and representative quality with explicit spending authorization. The offline parser caps 1–3 receipt records and 20 lines each; separate server enforcement of the corresponding image and output limits is still missing. Review and test the server enablement path separately. Until then this feature is not complete or available.

The local parser treats dates and currencies as literal strings and amounts as decimal strings; it does not infer missing values. Numeric cells allow at most 15 significant digits and four fractional digits, with a period as decimal separator: localized strings such as `3,25`, exponent notation and separators are rejected, while negative zero is accepted. CSV has a UTF-8 BOM and one `summary` row per receipt followed by `line` rows; totals occur only in the summary row. Evidence and warnings are JSON text on that row. Text cells are quoted, and potentially formula-like text, including full-width prefixes and leading control characters, receives a leading apostrophe; legitimate names such as `-Mart` are therefore altered. Dates and currency are also apostrophe-prefixed to discourage spreadsheet locale coercion. These checks are not proof of model accuracy, decoded-image safety, spreadsheet behavior in every product or browser accessibility.

The standalone review component supports adding and removing lines, a one-removal undo, and field-specific export errors. It allows an all-empty model line to load for editing, but rejects it at export. Users must undo or keep a pending removal before export. Screen-reader and physical-device behavior remain unverified; integration and human accessibility review are still required.

Reference scope: section 2 of the Pro Cloudflare audit specifications and existing PR #107's receipt extractor were inspected. PR #107 uses a different schema, up to four images and a fallback with unverified image-token assumptions; it was not reused or changed. This partial lane intentionally does not update `docs/pro-auth-spec.md` or register a price.

Before enabling the editor, handle model-supplied empty or whitespace-only descriptions when checking blank lines, improve digit-limit guidance and error state after undo, and test multiple receipts and middle-line removal. Human screen-reader and physical-device behavior remain unverified.
